# تعريب Rain-erp

تتابع [Issue #15](https://github.com/so7ob/Rain-erp/issues/15) التعريب الكامل، وتخص [Issue #16](https://github.com/so7ob/Rain-erp/issues/16) البنية الأساسية والكتالوج المشترك. وجود العربية في قائمة اللغات لا يثبت اكتمال تعريب الوحدات.

## القرارات المعتمدة

- العربية الفصحى افتراضية عند غياب اختيار صالح؛ يحفظ اختيار المستخدم السابق للإنجليزية أو الصينية.
- الأرقام `0–9` والتقويم ميلادي. تبقى العملات والمبالغ والتوقيت وقواعد الأعمال كما هي.
- العربية `rtl` والإنجليزية والصينية `ltr`؛ يحتاج كل تخطيط ومكوّن قبولًا بصريًا مستقلًا.
- بيانات المستخدم والأسماء المخصصة لا تترجم تلقائيًا ولا تستبدل في قاعدة البيانات.
- تشمل الخطة الوحدات الاختيارية دون تفعيلها في التطبيق المشغّل.

## الكتالوجات وتبديل اللغة

توجد الكتالوجات في `frontend/src/locales/{ar,en,zh-CN}/`. يحتوي `shared.json` النصوص المشتركة؛ تضاف ملفات الوحدات مثل `erp.json` بمفاتيح دلالية تحت اسم الوحدة، مثل `erp.product.name`. يحمّل التطبيق اللغة المطلوبة عند الحاجة، ويحمل الإنجليزية للاحتياط. تكرار المفتاح بين الملفات خطأ.

يضاف كل مفتاح ومعاملاته إلى اللغات الثلاث. لا يقبل مفتاح عربي مفقود أو فارغ اعتمادًا على اللغة الاحتياطية. تطابق المفاتيح المشتركة لا يعني استخراج جميع النصوص الثابتة.

تحدّث آلية التبديل رسائل Vue وElement Plus واتجاه المستند والاختيار المحفوظ دون إعادة تحميل الصفحة. لا يستبدل انتهاء تحميل لغة قديمة اختيارًا أحدث. تحويل العناوين والتسميات الملتقطة مرة واحدة عند إنشاء الشاشات إلى قيم تفاعلية جزء من دفعات تلك الشاشات.

تعتمد صيغ الوقت النسبي على `Intl.RelativeTimeFormat` بما يشمل المثنى والجمع، مع أرقام لاتينية. ترسل طلبات Axios، بما فيها تجديد الجلسة، اللغة الحالية في `Accept-Language`. لا يثبت إرسال الرأس وحده تعريب جميع رسائل API.

تضيف [دفعة الدخول والملف الشخصي #19](https://github.com/so7ob/Rain-erp/issues/19) كتالوج `auth.json` للغات الثلاث، وتسميات الحقول والتحقق ورمز QR وSSO وربط الحسابات. تتغير رسائل أخطاء الحقول الظاهرة عند تبديل اللغة مع حفظ المدخلات، وتبقى حدود التحقق الأصلية كما هي. صححت صياغة الحدود التي كانت تختلف عن قواعدها: كلمة مرور الملف الشخصي من 4 إلى 16، واسم المنشأة في استعادة كلمة المرور من 2 إلى 20.

يفحص اختبار المصدر استخراج النصوص الثابتة من شاشتي الدخول والملف الشخصي. الاسمان الصينيان الافتراضيان في حقل `tenantName` داخل `Login/SocialLogin.vue` و`Login/components/MobileForm.vue` معرفا منشأة أصليان يحفظان للتوافق؛ يحدّ الاختبار الاستثناء بالملف والحقل والقيمة. لا يترجم اسم العميل أو التطبيق الخارجي أو نطاق OAuth المخصص تلقائيًا.

تعمل اختبارات المتصفح ببيانات وطلبات API محاكاة، وتشمل أحجام العرض والمظهرين وتبديل اللغة ولوحة المفاتيح. يفحص axe صفحة الدخول ومحتوى الملف الشخصي المملوك؛ تبقى الواجهة المشتركة ورسائل الخادم والأدوات المضمّنة ضمن القبول الشامل اللاحق. راجع [حدود الاختبارات وأوامرها](testing.md#authentication-and-profile-browser-checks). لا ترفع هذه الدفعة حالة أي وحدة إلى قبول التعريب الكامل.

## لغة الخادم وعقد الأخطاء

تضيف [دفعة #22](https://github.com/so7ob/Rain-erp/issues/22) مرشح لغة قبل المصادقة وتشفير API والتحقق. يحل `Accept-Language` للغات الثلاث، وأولوياتها وأشكالها الإقليمية المدعومة، ويعيد `Content-Language` و`Vary: Accept-Language`. تعود اللغة غير المدعومة أو المشوهة إلى الصينية السابقة. يحافظ غياب الرأس على الرسائل الأصلية وسلوك التحقق السابق، ويستعاد سياق الخيط بعد كل تمرير للطلب، بما فيه تمرير `ASYNC` والخطأ.

توجد كتالوجات الخادم في `src/main/resources/i18n/<module>/`: الإنجليزية في `messages.properties` للاحتياط، والعربية في `messages_ar.properties`، والصينية في `messages_zh_CN.properties`. يكتشف `MessageSource` كتالوجات الوحدات الموجودة في مسار التطبيق؛ يفحص اختبار المصدر أيضًا كتالوجات الوحدات غير المفعّلة. تشمل الدفعة 40 رسالة مشتركة و15 رسالة للنظام والمصادقة، ولا تعني اكتمال تعريب النظام أو التحقق من الوحدات الاختيارية.

يحمل `ErrorCode` مفتاحًا دلاليًا اختياريًا، مثل `system.oauth2.refreshToken.expired`. تبقى الأرقام كما هي، ولا تستخدم للبحث عن ترجمة؛ يحمل خطآن بالرقم `400` مفتاحين مختلفين بحسب المعنى. تحتفظ استثناءات الخدمة ونسخ `CommonResult` بالمعاملات حتى تنسيق `msg` عند كتابة JSON. تبقى `code` و`msg` و`data`، ويضاف `messageKey` عند توفره؛ لا ترسل المعاملات الداخلية. تستخدم القوالب `{0}` و`{1}`، وتحول قيم الرسائل إلى نصها الأصلي قبل التنسيق، مع بقاء بيانات الاستجابة وأنواعها ودقة المبالغ كما هي. تحتفظ الأخطاء المستلمة عبر JSON بنصها المكتمل إذا لم تتوفر معاملاتها، بدل إظهار رموز تنسيق غير مربوطة.

تستخدم رسائل تحقق الحقول مفاتيح مثل `@NotBlank(message = "{common.validation.required}")`، ويمكنها استخدام معاملات Hibernate مثل `{min}` و`{max}`. تختار الطبقة لغة الرسائل المملوكة قبل التخزين المؤقت للتحقق، بما يحفظ الرسالة الصينية السابقة للطلب دون رأس، ويترك رسائل Hibernate القياسية السابقة كما هي. تفحص اختبارات API التبديل المتتابع بين اللغات والطلب القديم دون لغة.

يعتمد تجديد الجلسة في الواجهة على مفاتيح ثابتة، ويشترك منتظرو الجلسة نفسها في محاولة واحدة. ترفض المحاولة الفاشلة جميع المنتظرين دون إعادة طلباتهم، ولا تبدأ استجابة `401` بعد إعادة المحاولة حلقة تجديد. يحدد `common.error.unauthorized` فشل مصادقة الجلسة؛ تعرض أخطاء المجال ذات المفاتيح المختلفة دون إخراج المستخدم، حتى لو حملت الرقم `401`. يبقى مسار التوافق للحالة القديمة التي لا تحمل مفتاحًا. ترتبط المحاولات بهوية مستخدم الدخول ومنشأته الأصلية؛ لا تستبدل استجابة قديمة جلسة جديدة، ولا توضع بيانات اعتماد التجديد في بيانات تعريف طلبات Axios. ترسل لغة التجديد ومعرّف المنشأة في الطلب نفسه، ويظل اختيار اللغة محفوظًا عند إعادة الدخول.

ما زالت رسائل الوحدات غير المحولة، والتعليقات النصية للتحقق، وأسباب مزودي CAPTCHA، وسياق المهام الخلفية والتدفقات، وقواميس العرض وتخزينها بحسب اللغة والمنشأة الزائرة، والمخرجات والاستيراد والتصدير ضمن الدفعات التالية. اختبارات هذه الطبقة معزولة، ولا تثبت نشرها على خادم التشغيل الحالي. تبقى حالات قبول الوحدات معلقة تحت #15.

## الحصر والقبول

```bash
cd frontend
corepack pnpm test
corepack pnpm i18n:inventory
corepack pnpm i18n:check
node scripts/localization-inventory.mjs --details
corepack pnpm i18n:accept
```

يحفظ الحصر الملخص في `docs/localization-inventory.json`، ويطابقه الفحص مع المصدر والكتالوجات. يطبع `--details` النصوص المرشحة ومواضعها، دون إعدادات التشغيل أو بيانات المستخدم. يكشف المحلل نصوص قوالب Vue وخصائص العرض والتعبيرات والنصوص السياقية في JavaScript وTypeScript. أعداد Java حصر للملفات وثوابت الأخطاء ورؤوس Excel ورسائل التحقق فقط.

النصوص المنشأة وقت التشغيل، وCSS، والصور، والمكونات الخارجية ومخرجات الخادم الديناميكية تحتاج مراجعة مستقلة. تبقى أخطاء تحليل القوالب ظاهرة. جميع الوحدات في حالة `pending-acceptance`؛ يفشل `i18n:accept` صراحة حتى استكمال القبول تحت #15. أعداد المواضع ليست نسبة إنجاز أو عدد نصوص فريدة.

يتطلب قبول كل وحدة استخراج النصوص ومراجعتها لغويًا، واختبار القوائم والقواميس والبيانات المخصصة وAPI والصلاحيات، والاستيراد والتصدير والطباعة عند وجودها، والمتصفح ولوحة المفاتيح وaxe والنص المختلط وعرضي `375` و`1280` والمظهرين الفاتح والداكن. توثق الثوابت التقنية المستثناة حسب الموضع والسبب. تتحقق الوحدات الاختيارية في بيئة معزولة؛ بناء النظام والبنية التحتية لا يغطيها.

## قاموس المصطلحات

| المفهوم | المصطلح العربي |
| --- | --- |
| Tenant | المنشأة، عندما يشير إلى مساحة المؤسسة في الواجهة |
| User / role / permission | مستخدم / دور / صلاحية |
| Product / item | منتج / صنف بحسب السياق |
| Inventory / warehouse | مخزون / مستودع |
| Purchase order / sales order | أمر شراء / أمر بيع |
| Stock receipt / issue | إدخال مخزني / إخراج مخزني |
| Customer / supplier | عميل / مورد |
| Account / journal / voucher | حساب / يومية / سند، بحسب السياق المحاسبي |
| Debit / credit | مدين / دائن |
| Approve / reverse approval | اعتماد / إلغاء الاعتماد |
| Status / enabled / disabled | حالة / مفعّل / معطّل |
| Export / import / upload | تصدير / استيراد / رفع |
| Dictionary / dictionary value | قاموس / قيمة القاموس |

تبقى أسماء المنتجات والعلامات والمعرّفات مثل `OAuth 2.0` كما هي. تراجع المصطلحات المحاسبية في سياق الشاشة والمخرجات، ولا تستبدل الكلمات آليًا في بيانات المستخدم.

## التكاملات والدفعات المتبقية

- **JimuReport وJimuBI:** تأتي واجهاتهما من اعتماد Java داخل iframe؛ يشمل العمل الغلاف وتمرير اللغة المدعومة، وتسجل نتيجة دعم العربية الفعلية لكل مصمم.
- **GoView:** خدمة منفصلة لا يوجد مصدرها هنا؛ تترجم الواجهة المملوكة وتمرر اللغة حيث تدعمها الخدمة، وتسجل الواجهة الخارجة عن السيطرة.
- **روابط التوثيق والخدمات الخارجية:** يترجم عنوان الرابط؛ محتوى الموقع الخارجي خارج مصادر المستودع.
- **المحررات ومصممو النماذج والمخططات المستوردة:** تحتاج محولات عربية داخل المشروع وقبول RTL مستقلًا عن كتالوج Vue.

تغطي الدفعات التالية النواة والشاشات المشتركة، ورسائل الخادم، والقوائم والقواميس، ثم وحدات الأعمال وبقية الوحدات، ثم قبول المخرجات والمتصفح. تبقى #15 مفتوحة حتى اكتمالها. نشر التطبيق وتفعيل الوحدات وتعديل بيانات التشغيل أعمال منفصلة.
